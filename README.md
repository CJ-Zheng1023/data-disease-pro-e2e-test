## 二、测试数据保护策略（重要）

本项目的所有用例都遵循“**不动存量数据**”原则：

1. **统一标识**：用例创建的数据（标注任务、AI 会话等）名称/内容中统一携带
   `E2E-AUTO` 标识 + 时间戳 + 随机后缀（见 `config/constants.py`、`src/utils/test_data.py`），
   人工排查时一眼可辨，自动化清理时精准定位；
2. **自建自删**：删除类用例（删除标注任务/标注集、删除会话、删除消息、删除课题/临床试验/数据集）
   全部针对“用例自己创建的数据”，并在用例结束后通过夹具兜底清理（即使用例失败也会执行）；
   所有子级数据（课题下的临床试验/影像数据集、标注任务下的标注集等）随顶级自建数据一并清理；
   “导入到课题 / 导入到临床试验 / 从数据集导入”等数据搬运用例，目标均为自建数据，
   不触碰存量数据；
3. **密码恢复**：修改密码用例完成后，`password_restorer` 守卫会自动把账号密码
   恢复为初始密码。由于测试账号初始密码可能是历史遗留的**弱密码**（不满足现行
   前端安全策略），恢复动作通过“**接口 + RSA 加密**”完成（`src/utils/password_tools.py`），
   并会重新登录验证，恢复失败时会显式报错提醒人工介入；
4. **环境自检**：`scripts/check_environment.py` 可随时验证环境无残留：
   - 原始密码可登录；
   - 无携带 `E2E-AUTO` 标识的会话 / 标注任务 / 课题残留。

```bash
python scripts/check_environment.py
```

## 三、快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
python -m playwright install chromium
```

### 2. 配置环境（可选）

默认直连开发联调环境。如需切换，可通过环境变量或项目根目录 `.env` 文件覆盖：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `E2E_BASE_URL` | `http://10.13.37.154/` | 目标环境地址 |
| `E2E_USERNAME` | `zhengchj1` | 测试账号 |
| `E2E_PASSWORD` | `123456` | 测试账号初始密码 |
| `E2E_DEFAULT_TIMEOUT_MS` | `20000` | 元素等待超时 |
| `E2E_NAV_TIMEOUT_MS` | `60000` | 页面跳转超时 |
| `E2E_AI_TIMEOUT_MS` | `120000` | AI 回答等待超时 |
| `E2E_VIEWPORT_WIDTH/HEIGHT` | `1920x1080` | 浏览器视口 |

`.env` 示例：

```ini
E2E_BASE_URL=http://10.13.37.154/
E2E_USERNAME=zhengchj1
E2E_PASSWORD=123456
```

### 3. 运行测试

```bash
# 全量运行（默认无头模式，结果写入 allure-results/）
pytest

# 有头模式运行（观察浏览器操作，适合调试）
pytest --headed

# 放慢操作速度，便于人工观察
pytest --headed --slowmo=500

# 只运行冒烟用例
pytest -m smoke

# 运行单个模块 / 单条用例
pytest tests/test_30_chat.py
pytest "tests/test_10_database.py::TestDatabaseDetail::test_enter_detail"
```

### 4. 查看 Allure 报告

```bash
# 需要已安装 Allure 命令行（https://allurereport.org/docs/install/）
allure serve allure-results     # 本地启动在线报告
allure generate allure-results -o allure-report --clean   # 生成静态报告
```

失败自动留痕：

- Allure 报告中自动附带**失败截图**与**失败现场页面源码**；
- `screenshots/` 目录保留截图文件；
- `logs/run-YYYYMMDD.log` 记录完整运行日志。

### 架构说明

- **页面对象模式（POM）**：每个模块一个页面对象文件，页面对象只负责“怎么操作界面 /
  怎么读界面状态”，业务断言全部写在用例层；
- **组合优于继承**：`LayoutHeader`（主框架）作为组件对象被登录、修改密码、退出登录
  等用例组合复用；页面对象之间不重复实现菜单、用户下拉等公共区域；
- **登录态复用**：测试会话开始时通过 UI 真实登录一次并保存 `storage_state`，
  后续用例直接复用登录态（快且稳）；登录 / 退出 / 修改密码用例使用
  `@pytest.mark.no_auth` 标记，运行在干净的未登录上下文中；
- **UI 断言 + 接口清理**：断言全部走 UI（保证真实性）；数据的建立与兜底清理走接口
  （保证失败场景下也能清干净，且不依赖 UI 是否可用）；
- **用例编号排序**：文件按 `test_00_` ~ `test_60_` 编号，保证修改密码等“有副作用”
  的用例在稳定顺序下执行，降低相互影响。

## 五、自定义 marker

| Marker | 用途 |
| --- | --- |
| `smoke` | 冒烟用例（核心链路，快速反馈），`pytest -m smoke` |
| `no_auth` | 不使用已保存登录态（登录/退出/修改密码场景自行登录） |
| `data_cleanup` | 涉及测试数据创建与清理的用例 |

## 六、常见问题排查

| 现象 | 排查方向 |
| --- | --- |
| 登录态失效导致大面积失败 | 删除 `.runtime/storage_state.json` 后重跑（会话开始时自动重新登录） |
| AI 回答等待超时 | 调大 `E2E_AI_TIMEOUT_MS`，或检查后端 AI 服务状态 |
| 修改密码用例异常中断 | 运行 `python scripts/check_environment.py` 确认密码已恢复；若未恢复，检查用例日志中的恢复流程输出 |
| 环境切换后用例失败 | 确认 `.env` / 环境变量中的 `E2E_BASE_URL` 与实际环境一致 |
| 个别用例显示 SKIPPED | 环境缺少对应数据时优雅跳过（如专病库无影像数据/无患者数据/无 ID 字段），不影响其余用例结论 |
| 想观察浏览器执行过程 | `pytest --headed --slowmo=300` |
